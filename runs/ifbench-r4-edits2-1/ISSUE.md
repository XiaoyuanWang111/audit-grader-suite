## Contract changes

Each change was made after reading the grader code (2026-11-10T23:54:15Z) and is marked with its
reason. The contract readings that the fixtures use are the proposals in `audit/CONTRACTS.md` v1
plus these entries; no proposal was changed to match the grader.

- C1 `D-punct-set`: add reading C, "the six sentence marks `. , ? ! ; :` plus an interrobang".
  Reason: the grader uses this set; a careful reader can defend "standard punctuation" as the basic
  sentence marks, which v1 did not list. Proposal unchanged (full English set).
- C2 `D-vowel-paragraph` (new): reading A, the paragraph count is not scored (or paragraphs are
  separated by blank lines, G6); reading B, the response must be a single line. Reason: v1 did not
  say whether "Write a paragraph" is scored. Proposal A.
- C3 `D-word-split` (new, replaces `D-hyphen`): reading A, contractions ("don't"), hyphenated
  compounds and decimals are one word; reading B, they split at the apostrophe, hyphen or point
  (`\w+` tokens). Reason: v1 only named hyphens. Proposal A.
- C4 `D-wrapper` (new, generalises `D-csv-wrapper`): whether a lead-in or closing sentence around a
  requested artefact (CSV, list, template, country list) is allowed. Proposal: allowed only where
  the instruction does not ask for the artefact alone; v1 readings per check unchanged.
- C5 `D-csv-space` (new): whether a space after the delimiter (`ID, Country`) still gives the named
  columns. Proposal: yes (the space is formatting).
- C6 `D-change-case` (new): whether changing only the case of the first word ("use" for "Use")
  counts as changing it. Proposal: no.
- C7 `D-options-label` (new, 2026-11-11T00:09:37Z): whether an option given without its label
  punctuation ("A" for "(A)", "b" for "b)") is that option. Proposal: yes (the letter identifies the
  option). Reason: a reference unit test asserts the strict reading (line 326).
- C8 `D-paren-match` (new, 2026-11-11T00:09:37Z): whether closing brackets must match the opening
  type for the nesting to count. Proposal: yes ("correctly matched"). Reason: a reference unit test
  (line 275) asserts a pass for a 20-level nest closed with mismatched types.
- C9 G5 refinement (2026-11-11T00:21:09Z): an ellipsis (`...` or `…`) followed by whitespace and a
  lowercase word does not end a sentence. Reason: panel responses quote texts with elisions ("Acts of
  violence ... are ... revolutionary."); a careful reader reads one sentence there, and v1's mechanical
  rule split it. This narrows sentence ends; it was not made to match the grader (punkt behaves the
  same way here, so it reduces disagreements that were artefacts of the v1 rule).
- C10 `D-japanese-mixed` (new, 2026-11-11T00:21:09Z): whether a whitespace token that mixes Japanese
  and Latin letters ("Fabricや...") is "in Japanese". Proposal A: no (all letters Japanese, v1 text);
  reading B: yes if it contains Japanese script. Reason: all-Japanese panel responses have few spaces,
  so tokens embed Latin product names.
- `D-wrapper` is measured with three switches: `-csv` (proposal: lead-in sentence and code fence
  allowed), `-template` (proposal: the response starts with "My Answer:"), `-list` (proposal:
  country lines only, v1). `D-vacuous` covers `D-indent-single` (proposal: one line is no stairs).

## Step 1, post-contract part (pins that only the code shows)

Recorded 2026-11-10T23:54:15Z.

- Harness (`grader.py`): strict = `check_following(response)` on the response as stored, after a
  guard that fails empty or whitespace-only responses; loose = the same checks on 8 variants
  (response, `*` removed, first line removed, last line removed, both removed, and the `*`-removed
  versions of the three) and a pass if any variant passes. No exception handling: an exception in a
  checker propagates. Responses are looked up by prompt text (`prompt_to_response[inp.prompt]`); the
  300 prompts are distinct, so no collision in this dataset.
- `eval_instruct.py`: `load_dataset("allenai/IFBench_test", split="train")` with **no revision**;
  generation `do_sample=False, temperature=0, max_gen_toks=1024`; primary metric
  `strict_prompt_accuracy`. The response extraction rule and chat template handling live in
  Evalchemy modules (`eval.sources.common.text_specs`, `eval.task`) that are not in the case
  (unverified).
- kwargs types: HF `datasets` gives int for `n, m, n_start, n_end` (int64 columns) and float for
  `N, small_n, percentage, min_words, max_words` (double). The audit loads rows with
  `pyarrow.Table.to_pylist()`, which gives the same types (`audit/lib/harness.py`). Re-dumped
  `audit/frozen/dataset_rows.jsonl` with these types: sha256
  `f75c887099833cfb7e4f1e2946881f870d38ccd06e2509b892d927021dd861b2`; per-row hashes
  `audit/frozen/dataset_row_sha256.tsv` sha256
  `81a1ff1b6fb1578ff92d2f6cb629d1b64dc352987eb4279286dac65664b1f703` (these replace the pandas
  dump hashes recorded above, which had int kwargs as floats).
- NLTK: the grader uses `sent_tokenize` (punkt_tab), `word_tokenize`, `pos_tag`
  (averaged_perceptron_tagger_eng), `RegexpTokenizer(r"\w+")` and `corpora/stopwords` (english).
  At import, `instructions.py` creates `<package dir>/.nltk_data`, puts it first on
  `nltk.data.path`, and sets `NLTK_DATA` to it when unset; `instructions_util.py` then calls
  `nltk.download(<resource>)` for any of punkt, punkt_tab, stopwords, averaged_perceptron_tagger_eng
